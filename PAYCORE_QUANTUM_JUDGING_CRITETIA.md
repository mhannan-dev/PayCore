Judging criteria
1. User experience and presentation
Intuitive interface and onboarding: A clean, accessible, and responsive design (desktop/mobile) that enables first-time users to complete actions quickly with clear status feedback and plain-language error handling.
Compelling narrative and delivery: A concise, confident pitch that clearly articulates the problem statement, user journey, and product value.
2. Demo clear and well-structured
Reliable end-to-end execution: A well-paced, reproducible walkthrough showing the core flow, agent actions, and edge cases working reliably on testnet.
Verifiable on-chain activity: Transparent proof of live execution, including visible transaction hashes, explorer links, and verifiable state changes.
3. Comprehensive documentation
Turnkey setup and architecture: A clear README with architectural flowcharts, environment variable specifications, testnet addresses, and working step-by-step reproduction instructions.
Integration depth and specifications: Detailed documentation explaining how each platform technology is integrated, complete with API examples, known constraints, and future roadmap items.
4. Innovation and originality
Fresh problem-solving: A distinct, non-derivative approach that goes beyond standard templates, sample tracks, and existing hackathon submissions.
Creative agentic mechanics: Novel implementations of autonomous agents, agentic payment primitives, or emerging on-chain business models.
5. Technical quality and platform integration
Idiomatic platform integration: Deep, correct adoption of native platform tooling, including smart accounts, scoped session keys, spending limits, and identity primitives.
Resilience and code excellence: Clean, well-structured, and tested code that robustly handles retries, asynchronous confirmations, edge cases, and smart contract security best practices.
6. Real-world utility and market potential
Workflow fit and user demand: A practical solution targeting a well-defined audience with genuine demand, designed to slot smoothly into real merchant or automated agent operations.
Path to scale and monetization: A viable business model supported by a sensible distribution plan and a realistic roadmap toward production and mainnet adoption.
7. Safety, trust and controls
Proactive risk parameters: Strict adherence to least-privilege permissions, session expiration, and spend caps to guard against compromised keys, runaway spending, or prompt injection.
Auditability and user sovereignty: Clear transaction review and approval steps, instant revocation mechanisms, full user data privacy, and verifiable on-chain audit trails.
8. Ecosystem contribution (reusable, open source)
Modular, open-source code: Cleanly licensed, extensible codebases featuring reusable SDKs, component libraries, or scaffolding templates that other builders can easily adopt.
Community and developer value: High potential to serve as an ecosystem infrastructure building block alongside actionable developer feedback, bug reports, and platform contributions.
